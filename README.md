# Little Turtle Planner 🐢

Бесплатный локальный планнер на русском. Требования: [PROJECT_SPEC.md](PROJECT_SPEC.md).

## Разработка

Node.js 22+; `npm ci`, затем `npm run dev`. Проверки: `npm test`, `npm run build`. Production-проверка: `npm run preview` после сборки. Service worker активен в production-сборке.

## Публикация

Разместите содержимое `dist` на любом бесплатном статическом HTTPS-хостинге (например GitHub Pages или Cloudflare Pages). Для Pages используйте Actions: npm ci → npm test → npm run build → загрузка dist через actions/upload-pages-artifact → actions/deploy-pages. Относительные пути поддерживают размещение в подпапке. Сервер/API не нужны.
Android: меню браузера → «Установить приложение». iPhone: Safari → «Поделиться» → «На экран Домой». HTTPS обязателен (localhost разрешён для разработки). После первого открытия дождитесь загрузки приложения перед уходом офлайн.

## Данные

IndexedDB в текущем браузере/профиле. Экспортируйте JSON через «Настройки» регулярно: очистка данных браузера удаляет локальные записи. Импорт заменяет данные только после валидации и подтверждения. Приватный режим и запрет хранилища могут ограничить сохранение. Обновления приложения не удаляют базу; доступное обновление применяется по кнопке, после сохранения изменений.

## Модель дат

Локальные yyyy-MM-dd; недельный срок — воскресенье. Просроченные задачи вычисляются как сегодняшние без изменения исходного срока. Отметки привычек хранятся отдельными датами; изменение расписания влияет на отображение плановых дней в истории, но не удаляет фактические отметки.

## Браузерные проверки

`npx playwright install chromium`, затем `npm run build` и `npm run test:e2e`. При использовании системного Chromium: `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`. Playwright самостоятельно запускает preview. Сценарии проверяют CRUD, календарь, смену локального дня, офлайн-перезагрузку, резервные копии, ошибки записи и адаптивность. Реальную установку на iOS/Android нужно проверить на устройстве после HTTPS-публикации.

В репозитории подготовлены CI-проверки и ручной workflow публикации: Settings → Pages → Source: GitHub Actions, затем Actions → «Опубликовать на GitHub Pages» → Run workflow. Автоматическая публикация при push отключена.

## Структура

- `src/models.ts`, `src/logic.ts` — модели и календарные правила.
- `src/storage.ts` — IndexedDB и атомарные обновления между вкладками.
- `src/usePlanner.ts` — действия, загрузка, актуализация даты и резервные копии.
- `src/components` — формы, календарь, задачи и SVG-талисман.
- `src/App.tsx`, `src/style.css` — главный экран и адаптивная тема.
- `public` — локальные иконки; `vite.config.ts` — manifest и офлайн-кеш.

Все ресурсы приложения локальные, внешние API, шрифты и аналитика не используются. Синхронизации между устройствами нет: перенос выполняется JSON-копией. Индивидуальное расписание хранится в текущей версии привычки; его редактирование не удаляет историю отметок.

## Этапы первой версии

| Этап                     | Основные файлы                                    | Как проверить                                            |
| ------------------------ | ------------------------------------------------- | -------------------------------------------------------- |
| 1. Основа и тема         | `package.json`, `vite.config.ts`, `src/style.css` | `npm run build`                                          |
| 2. Главный экран         | `src/App.tsx`, `TaskSection.tsx`                  | Мобильный и широкий экран                                |
| 3. Задачи                | `TaskEditor.tsx`, `src/logic.ts`                  | Создать, изменить, выполнить, вернуть и удалить задачу   |
| 4. Привычки              | `HabitEditor.tsx`, `src/usePlanner.ts`            | Настроить три расписания, проверить отметки и сортировку |
| 5. История               | `HabitDetail.tsx`                                 | Открыть календарь и переключить месяц                    |
| 6. Талисман              | `Turtle.tsx`, `public/turtle.svg`                 | Выполнить привычку, проверить reduced-motion             |
| 7. Данные и офлайн       | `src/storage.ts`, `vite.config.ts`                | Перезагрузка без сети, экспорт/импорт                    |
| 8. Проверки и публикация | `src/*.test.ts`, `e2e`, `.github/workflows`       | `npm test`, `npm run test:e2e`, `npm run build`          |

Проверено в Chromium с мобильным viewport, включая локальную полночь, сохранение истории, ошибки IndexedDB и восстановление копии. Установка на реальные устройства и публикация остаются ручными проверками после размещения на HTTPS-хостинге.
